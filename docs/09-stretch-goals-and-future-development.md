09 — Stretch Goals and Future Development

Expansion paths governed by evidence and product value

# Expansion rule

Future work should deepen observation, experimentation or learning. Do not turn the Observatory into a general AI chat product, a cloud platform or a sprawling interpretability suite unless the core instrument has proved valuable.

# Phase A — Deeper instrument

* Tuned-lens probes with published training procedure, evaluation and versioned assets.  
* Activation-patching or carefully bounded causal-tracing experiments on the small model.  
* Neuron/feature inspection only where the model and method support interpretable evidence.  
* Side-by-side backend or quantisation comparison with numerical tolerances.  
* Trace compression, tensor block streaming and larger context windows.  
* A reproducible model-export pipeline with continuous golden-fixture verification.

# Phase B — Modern model mode

* Add a compact contemporary model such as SmolLM2-class or another suitable browser model.  
* Expose only supported measurements; the UI capability contract must allow instruments to be absent.  
* Compare tokenisers, architectures and decoding behaviour without implying larger/newer is automatically better.  
* Use this mode to teach architectural differences rather than to chase benchmark performance.

# Phase C — Teaching platform

* Course authoring format for experiments with trace fixtures and validation predicates.  
* Instructor presentation mode with synchronised step control.  
* Shareable static trace bundles that do not require uploading prompts to a service.  
* Learner notebooks, reflection prompts and exportable completion evidence.  
* Certificate IV programming and AI-learning modules tailored to practical experimentation.

# Phase D — Collaborative observatory

* Optional encrypted trace sharing or static share links.  
* Peer annotations and compare-by-link without mandatory accounts.  
* Curated public experiment gallery with moderation and privacy controls.  
* Embeddable instruments for articles, lessons and talks.  
* Server features only after the local-first product proves the need.

# Possible specialist instruments

| Instrument | Value | Integrity requirement |
| :---- | :---- | :---- |
| Tokenizer comparator | Compare BPE/tokeniser boundaries across models | Use exact tokeniser assets |
| Quantisation microscope | Show rank/probability changes by dtype | Validate against full-precision fixture |
| Calibration bench | Compare predicted confidence with a dataset outcome | Define dataset and metric carefully |
| Prompt perturbation grid | Systematic controlled edit comparisons | Track one-variable changes |
| Representation neighbourhood | High-dimensional nearest neighbours plus projection | Separate exact similarity from projection |
| Architecture gallery | Compare GPT-2-style and newer compact blocks | No false one-to-one mapping |

# Public-project opportunities

* Open-source the trace schema and deterministic sampler as reusable packages.  
* Publish an interactive essay showing how the Observatory was built and what it cannot reveal.  
* Offer a small verified trace corpus for teaching and regression testing.  
* Invite interpretability researchers or educators to review integrity language.  
* Create a conference/demo mode focused on the branch chamber and one dramatic but honest experiment.

# Decision gates

| Gate | Evidence required | Decision |
| :---- | :---- | :---- |
| Live-path viability | Cross-browser inference and memory measurements | Keep model, reduce outputs or change target |
| Learning value | Users complete experiments and articulate correct concepts | Expand experiments or simplify |
| Branch value | Users repeatedly create and compare branches | Make lineage central or reduce complexity |
| Modern model mode | Adapter can expose meaningful honest evidence | Add mode or retain GPT-2 instrument |
| Backend need | Clear sharing/collaboration demand | Introduce minimal service or stay static |
| 3D investment | Meaningful comprehension gain at acceptable performance | Keep, simplify or remove |

# Avoidable distractions

* User accounts, subscriptions and organisation management before a public audience exists.  
* Large-model support that reduces instrumentation to an opaque API.  
* An agent framework, plugin marketplace or universal model abstraction.  
* Custom cloud infrastructure for a static local-first prototype.  
* Gamification detached from genuine observation predicates.  
* Cinematic decoration that makes the scientific product slower or less clear.

# Long-term north star

A trustworthy open observatory where anyone can run a small model, manipulate its decoding process, compare counterfactual traces and learn what the evidence supports—while seeing clearly where measurement ends and interpretation begins.
